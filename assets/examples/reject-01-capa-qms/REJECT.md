**没有放 `CAPA-PRD.html`（388 KB）**：它是 `容器 + data.json` 的生成物，可由 data.json 重生成；
把生成物一起入库会让「产物到底是什么形态」出现两份可能不一致的副本。
（该 html 另有史料价值：它内嵌的是 **0.8.0 之前的容器**——没有 `--tw-max`、没有 `.ant-table.fixed`、
没有 `.ant-table.xs`。所以**不要拿它当渲染口径**，渲染一律用仓库当前容器。）

**为什么放在 `assets/examples/` 下的子目录、而不是同级**：

- 同级文件名 `example-0N-*.json` 是「教材清单」，`tests/check_docs.py` 的 `EXPECTED_EXAMPLES`
  逐名比对；把反样本混进去，等于让「照名单点货」这套判据多一个必须解释的成员。
- 子目录名以 `reject-` 开头，且**比教材深一层**，任何 `assets/examples/example-*.json`
  的 glob / `os.listdir` 都取不到它（实测见 §5）。命名上「reject」是给人和模型一起看的：
  **看到这个词就知道不该照抄**。

## 6. 读这份反样本时必踩的三个陷阱

### 陷阱 1：`P7 列宽声明率` 曾经报过 `0/9 = 0%`，那是**量具 bug**，不是产物事实

2026-10-26 之前，`props_of()` 用 `float(w)` 读列宽，`float("150px")` 抛 `ValueError` → 记成「未声明」。
两个页面**每列都写了 width**（list 11/11、overdue 9/9），只是写成 `"150px"` 这种**带单位的字符串**，
于是「11/11 全声明」被报成 `0/9 = 0%`，连带把病因从「写了列宽但没锁 `table-layout`」
误诊成「没写列宽」——**两种病、两种修法，误诊的代价是把需求单写错方向。**

现在已按容器 `colWidthStyle()` 的口径解析（`52` / `"52px"` 等价，`20%` 计入声明率但不计入 Σ 预算），
读数是 `11/11=100% / auto`。**仍红，但红在 `fixed` 那一半** —— 这才是这个产物真实的病：

- `类型` 声明 72 → 渲染 62（1440 档）；`不合格（潜在）事实陈述` 声明 330 → 渲染 238；
- 声明的宽在 auto 布局里只是「建议宽」，内容装不下时浏览器继续压。

**这个坑已经按需求单定了（2026-10-26）**：`P7` 就是 `W-00` 的运行时载体，**不拆成 P7a/P7b** ——
拆开之后 `0/8 + fixed` 会读出「P7b 绿」的半绿，而「只 fixed 不写 width」不是解法。
现在它输出 `declared=11/11 (100%) fixed=false → FAIL(原因=fixed)`，红的理由直接写在值里，
枚举 `declared / fixed / both`。

### 陷阱 2：证据文件 §3.3 的 `V1 表头折行` 复现不出来

容器里 `.ant-table th{...white-space:nowrap...}`（`assets/container/index.html:329`），
**th 永远不折行**。实测：list 页 12 列、overdue 页 9 列，`th` 行盒 > 1 的列数均为 **0/12、0/9**，
`scrollWidth > clientWidth+1`（被裁）也是 **0**。
把用户截图放大后逐列看，表头全部单行（`序号/措施单号/类型/不合格（潜在）事实陈述/来源/责任部门/发出日期/纠正纳期/剩余/超期/状态/操作`）。

折行只发生在 **td**：`类型` 的「纠正」竖成两行、`来源` 的「金属异物预警」竖排、`状态` 的「待验证」竖排、
`操作` 的「详情/编辑」上下各一行。**「表头折行」这条要撤回，「二字字段竖排」这条成立。**

### 陷阱 3：`内容宽 1074` 是**评审态**，不是产品态

`1074` 出现在 1440×757 档、`pane 1182`：它是**折了 PRD 的评审台**里的 Content 宽，占视口 **74.6%**。
真正的产品态（1440×900、无评审外壳）Content 宽是 **1392**，占 **96.7%**；1600×900 档是 **1552**，占 **97.0%**
（两档都是 `内容宽 + 0（产品态无页内导航）+ 48（.ant-content 左右 padding 24×2）= 视口`，闭合差 0）。
教材 `example-06` 有 208 的页内 `ant-sider`，同样两档闭合：`1184+208+48=1440`、`1344+208+48=1600`。
证据文件里写「产品态内容宽 1074」是术语混用；定阈值时先确认要卡的是哪一个数
（`check_ui_shape` 的 `contentBoxW` 与 `product.contentBoxW` 是两个不同的量）。

## 7. 纪律

1. **不许改 `CAPA-PRD.data.json`**。它的价值在于「原样冻结」；改一个字段，这份反样本就变成了我们自己造的夹具。
2. **不许把它当 few-shot**。SKILL.md / references 的示例清单里只能出现 `example-0N-*.json`。
3. **不写 gen 脚本**。它不参与「示例不手改 JSON」的比对（`check_generators.py`），因为本来就不该被重生成。
4. **不许脚本自动改写守卫基线**。`expected-fails.json` 是「人签过字的期望」；想看实测集用
   `python3 tests/check_reject.py --suggest`（只打 stdout，不落盘）。**自动更新基线 = 把守卫关掉**，
   而且关掉之后一切看起来都还是绿的。
5. 需求单改了判据口径 → §4 的期望 FAIL 集必须同步更新；**过期不更新比没有更坏**：
   它会变成一份「看起来在约束、实际已经失效」的名单。更新顺序：`--suggest` 看实测 →
   人确认差异的每一条都能解释 → 手改 `expected-fails.json` → 再跑一次 `check_reject.py`。
6. **任何在渲染期自动修正产物缺陷的兜底，都会同时解除反样本的复现能力。**
   兜底前必须先在**这份反样本**上跑一遍，看它有没有把红改绿；改绿了就不许进容器，要留在判据侧。
   **实测过的例子**：「每列都有 `width` 就自动补 `tableLayout:fixed`」——`run.sh` 757 条断言一条没动，
   但 CAPA 的 `类型` 从 62 回到 72、短字段折行 `33/39 → 0/39`、`P7` 两页由红转绿。
   那不是在修容器，是在**渲染时替产物把病治好**：判据的职责是看见病，不是替它吃药。
   同一份产物必须能在一年后还红在同几条上，否则这份反样本就只剩一张截图的作用。
