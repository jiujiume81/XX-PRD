# 容器选型准则（页面形态 / 对话框 / 抽屉 / 新页面）

> 适用场景：**先定页面形态（§0），再定对话框（Modal）、抽屉（Drawer）、新页面（Page）**。
> 选错容器是 B2B 系统最常见的体验债之一 —— 校验器会直接拦住最严重的几种（见 §5）。
>
> **顺序不能反**：形态定错（该做密表的做成卡片、该做卡片的做成 8 列密表），后面容器选得再对也救不回来。
> 拿到的需求是「一批单据要处理」，先读 §0；是「填一个表单 / 看一条详情」，直接读 §1。
>
> 本文件是**产品设计准则**，不是实现细节。落到容器里怎么写见 §7「映射到容器」。

---

## 0. 先判断形态：这是不是「作业型列表页」（形态 A）

本节只回答一个问题：**这个页面该不该做成「全宽列表 + 抽屉详情」**。

### 0.1 适用条件（Ant Design 的口径）

AntD 把列表页分成两类，判断标准是两条**同时**成立：

| # | 条件 | 怎么问自己 |
|---|---|---|
| 1 | **每条记录要露出很多字段** | 用户在列表上就要横向比对 6 个以上字段（单号 / 批次 / 数量 / 标准 / 状态 / 时间），而不是只看「名称 + 一句描述」 |
| 2 | **用户搜寻时有准确的查询条件** | 用户是带着「单号 / 批次 / 时间段 / 状态」来的，说得出来自己要找哪一条 |

两条都成立 → **查询表格**（本节的作业型列表页）。

**反例（最容易搞错的一条）**：用户主要靠「**浏览发现**」——不知道自己要找哪条，是翻着看、按分类逛、按推荐点进去 —— 那是**标准列表**（卡片或简单列表），**不是**作业型列表页。
把它做成 8 列密表，用户失去扫描入口；反过来，把作业单做成卡片宫格，用户一天点 200 次也找不到那一条。

**本项目的经验判据**（不是 AntD 原文，是 I-07 的实测口径）：**行 ≥20 且列 ≥8**。低于这个量级，密表带来的收益抵不过它的认知成本。

### 0.2 形态决策表

| 形态 | 长什么样 | 适用信号 | 反信号（出现就别选它） |
|---|---|---|---|
| **A 全宽列表 + 抽屉** | 单张表占满内容宽；点行右侧滑出 560 抽屉看详情 | §0.1 两条都成立，且行 ≥20、列 ≥8；用户要「扫一批、改其中几条」 | 主要靠浏览发现；每条记录要图文并茂；一屏只需看 3–5 条 |
| **B 卡片宫格** | 每条一张卡，2–4 列 | 记录带缩略图 / 封面；用户按视觉挑；条数 ≤50 | 字段多且要跨行比对；要排序或多条件筛选；条数上千 |
| **C 主上子下（`MasterDetail`）** | 上主表 + 下子表联动 | 一条主记录挂多条明细，且**要并排比对**（订单 → 商品行） | 明细自己是独立作业对象（有自己的状态与操作）；只是「点行看详情」（那是 A + 抽屉） |

**硬约束：形态 A 禁止放进 ≤640 的窄栏。** 8 列在 640 下每列不到 80px，主键列（任务单号 / 批次号）必然裁字。容器里出现这种情况只有一种原因 —— 左栏占位把中栏挤到 640（对应判据 P15 按档有不同阈值；窄栏兜底看画布宽，P17 只在 866 档判）；正确做法是折叠左栏或提供全宽预览，不是把列删掉。

一句话记法：**能扫读、要批处理 → A；靠眼睛挑 → B；主带明细且要对照 → C。**

### 0.3 列集按档位选（S5）

| 内容宽 | 档 | 常显列数 | 说明 |
|---|---|---|---|
| **866**（1440×900 折 PRD） | **行数与列数都验收** | **8** | 下面 0.3.1 就是这一档的预算 |
| **1026**（1600×1000 折 PRD） | **行数验收（P2b）/ 列数只作设计基准（P17 SKIP）** | **9** | 866 的 8 列 + 关联通知单；**逐列宽度待验证，见下方警示** |
| 1284（评审全宽，需折 nav） | 设计基准（不判） | 11 | 全表（需折 nav） |

> ⚠️ **1026 档没有实测产物**（P17 只判 866 档，在该档判 SKIP）。本文件对这一档只给「9 列」一个结论，**不贴逐列宽度，也不给 Σ** —— 1026 的 Σ 不是 1026（见铁律 2：唯一一套列集的 Σ 恒等于 866）；逐列宽度要等有真实 1026 产物后用真实文本量一遍再定，也不给任何「按比例拉伸」的推演值，避免被当成规范抄走。

三条铁律：

1. **列集在生成时定**，写进 JSON 的 `columns`；**运行时不切列** —— 同一页只有一套列集，容器不做列显隐开关。
2. 每列**显式 `width`**，`table-layout:'fixed'`，**唯一一套列集的 `Σwidth` 恒等于 866**（主设计档，±2）。1026 / 1284 是**同一套列在不同宽度下的表现**，不是另一套列，Σ 不随之变。
3. 每列 **≥48**（含序号列）。这是硬下限，不是建议值 —— 序号列写 44 会被判据打回。

#### 0.3.1 866 档列宽预算（Σ = 866，8 列）

| 列 | 宽 | 类型 | 对齐 | 为什么是这个宽度 |
|---|---|---|---|---|
| 序号 | **48** | `index` | 左 | P17 硬下限 48；等宽数字 |
| 任务单号 | **188** | text 等宽 | 左 | 主键，14px 下 `IQC-20261022-0020` 实测 161px（含 padding），**不许裁字** |
| 物资名称 | **125** | text + `ellipsis` | 左 | 长文本列，截断 + `title`；这一列可以裁 |
| 批次号 | **146** | text 等宽 | 左 | `LOT-A26-1022` 实测 120px（含 padding），不裁 |
| 取样·样品 | **88** | `num` | 右 | 两值一格 `86/120 kg`，`tabular-nums` |
| 质检标准 | **103** | text + `ellipsis` | 左 | 长文本列，截断；这一列可以裁 |
| 状态 | **80** | `tag` + 前置红点 | 左 | 「检验中」+ 8px 边距；再窄会贴边 |
| 操作 | **88** | `action` | 右 | 两个文字链 `28 + 6 + 28 = 62`，列内 64；间距必须 6px（10px 会折行 → 行高 34 跳到 63） |
| **合计** | **866** | | | 48+188+125+146+88+103+80+88 |

**三条不变量**（写完必须同时成立）：

- `Σwidth = 866`（±2）；
- **主键三列（任务单号 / 批次号 / 操作）不裁字** —— `scrollWidth ≤ clientWidth`；
- **`ellipsis` 配置列数 ≤3，且与真溢出列集合相等**（配了没溢出 = 假省略号；漏配 = 悄悄裁字）。本档实测恰 2 列：物资名称 / 质检标准。

> **1026 档不给逐列数**：见 §0.3 的警示 —— 只定「9 列（866 的 8 列 + 关联通知单）」这一个结论，逐列宽度待有真实产物后再量，**Σ 也不按 1026 闭合**（见 §0.3 铁律 2）。**禁止**把 866 的列按比例放大来凑 1026。

### 0.4 筛选区恒为两行三列（S7）

列表页的筛选区**不是**「一排输入框」，是固定结构：

```jsonc
{ "filterBar": "grid3" }   // Table 的 props；渲染器据此生成两行三列 + 独立动作行
```

| 项 | 规格 | 为什么 |
|---|---|---|
| 栅格 | **3 列 × 2 行**（字段 4–6 个）；字段 ≤3 个时一行 | 6 个条件一行必然挤成 6 行或控件只有 124 宽 |
| label | 固定 **76px，右对齐** | 右对齐让所有输入框左边界成一条竖线（P6 竖线极差 ≤4） |
| 控件宽 | **= 该档列宽 − 84**（label 76 + 间距 8），**±2**，且 **≥160** | 866 档 258.7 − 84 = **174.7**；1026 档 312 − 84 = **228.0** |
| 动作 | **独立一行**，右对齐 | 混进栅格会破坏 3 列对齐，也会把「查询」挤成第二个标题带按钮 |
| 总高 | **≤148**（实测 144） | 上限是判据（P3）；构成见方案 §4.2（两行栅格 + 动作行 + padding），实测比预算 139 多 5px（边框与行距），**上限 148 留了 4px 容差** |

**控件不许写 `min-width`。** 旧实现写过 `.qf{min-width:260px}`：6 个条件各要 260px，三列栅格一列只有 258px，于是每个控件都溢出、被挤成 **6 行 × 1 列**，筛选区从 40px 涨到 194px —— 这正是「搜索栏又高又窄」的机制。
宽度由栅格算，不由控件声明。要改宽度就改栅格列数或 label 宽，**不要给控件加下限**。

「查询」是筛选动作里唯一的 `primary`；「重置」是默认按钮。页面级 `primary` 总数见 §0.9 的 P12 口径。

### 0.5 密度三件套（S3 / S15）

| 项 | 规格 | 说明 |
|---|---|---|
| 列表 `Table.size` | **`'xs'`** | `.ant-table.xs`：`font-size:14px`、`padding:5px 12px`、`line-height:21px` → 内容盒 **32**，`tr.offsetHeight` 实测 **34**（多 2px 行内盒余量） |
| 详情 / 抽屉里的子表 | **`'small'`**（渲成 `.sm` 类） | 抽屉里不用跑「一屏几行」，用可读性换密度。**注意值是 `'small'` 不是 `'sm'`** —— `'sm'` 是 CSS 类名，写进 `props.size` 不生效 |
| 不写 `size` | **禁止** | 默认 `middle`，行高 48 —— 1440 档只剩 **6 折算 / 5 整行**（319 ÷ 48，折算含表头） |
| 表头 | `stickyHeader: true` | `position:sticky; top:0`；`border-collapse:separate` 下用 `box-shadow:inset 0 -1px 0` 补线 |
| 表体高度 | `maxHeight: "calc(100vh - 438px)"` | 438 = 表格顶 392 + 分页脚 **46**（实测；不是 36）。1600 档 **12 折算 / 11 整行**，1440 档 **9 折算 / 8 整行**（折算 = 可视高 ÷ 行高，分子含表头 34px；整行要扣掉表头） |
| 分页脚 | `stickyFooter: true` | 分页必须在首屏内（P16），且不随表体滚动消失 |

**字号口径（重要，别再写 13px）**：`.xs` 用 **14px**。方案原文曾写 13px，已被否定 —— 13px 会在页内多开一档字号（18 / 14 / 13 / 12 四档），与「页内 ≤3 档」的判据直接冲突；且 13 与 12 / 14 只差 1px，视觉上分不出，属于典型的伪档位。页内字号只允许 **18（标题）/ 14（正文）/ 12（辅助）**。

**行高口径**：设计值 32 是**内容盒**（5 + 5 + 21 + 1px 下边框），判据量 `tr.offsetHeight` 得到 **34**（多 2px 行内盒余量）。所以阈值是 **≤34**，不是 `==32` —— 写 32 会被实测 34 判红，然后有人去删边框或改 padding，那是改实现迁就判据。

**标题带三合一（S13）**：提示条、主操作行、工具条**不许各自成行**。三者都并进标题带（h1 左侧、操作右侧、提示压在 h1 下方一行 20px）。理由是可测量的：表格起点每多一行就少 1 行数据（34px），而这三样各自成行时实测多出 84px（表格起点从 392 涨到 476）。

**数值列（S14）**：数量 / 金额 / 比率一律 `align:'right'` + `num` 类（`font-variant-numeric:tabular-nums`）；单位与数值分离（数值 14px、单位 12px 次级灰字），**不要把单位拼进数值字符串** —— 拼进去后右对齐会错位，且无法按数值排序。

### 0.6 列表页禁止统计（S2）

- 列表页 `Content` 内 **`Statistic` 数量必须为 0**（判据 P1；只 `display:none` 不算，要删 DOM —— 三层噪音 P5 会抓到）。
- 要「看数量」：放进**标题带**，用 `Segmented` 切换视图（`全部 342 / 待检验 18 / 我负责 26`），**不占一行动线**。
- 要看「趋势 / 分布 / 排行」：**独立统计页**，列表页只留一个跳转入口（一行文字链，不是一张卡）。

三条独立理由（不是「占高度」一条）：① 统计卡把表格推到首屏外（每张 68–272px）；② 统计数字与筛选结果不同步，用户会问「为什么显示 342 但表里 18 条」；③ 卡片 = 第三层容器，直接违反 P5（三层噪音）。

### 0.7 六态：空态与零结果不是一回事

每个作业型列表页必须能渲染六态（`states[]`）：

| 状态 id | 场景 | 文案 | 动作 |
|---|---|---|---|
| `s-default` | 有数据 | — | — |
| `s-loading` | 首次加载 / 换页 | 骨架屏，筛选区与标题带保持可见 | — |
| `s-empty` | **真的没有数据**（本月还没建过） | 「本月还没有来料检验任务」 | **「去建检验任务」（default）** |
| `s-no-result` | **筛选后 0 条**（数据是有的） | 「没有符合条件的任务，试试清空筛选」 | **「清空筛选」**（不是 primary） |
| `s-error` | 服务不可用 | 「检验服务暂时不可用，请稍后重试」 | 「重试」 |
| `s-long-text` | 超长文本压测 | 用最长可能值渲染，验证列宽与省略号 | — |

**两者文案与动作都必须不同**：空态引导「创建」（用户还没有这个东西），零结果引导「改条件」（东西有，是筛没了）。共用一个「暂无数据」等于让用户不知道该建还是该查。

**空态动作用 default 样式**（标题带的「新建」已占掉本页唯一 primary 位）。若产品确要突出空态动作，则**空态时隐藏标题带主操作** —— 两者只能有一个以 primary 出现。默认取前者：空态是偶发态，标题带主操作是常驻入口，不该为偶发态让位。

写法：`Table.props.emptyText`（文案）+ `Table.props.emptyAction`（`{text, type?, icon?, id}`）；状态用 `overrides` 把 `data` 置空并改这两个 prop。

### 0.8 详情用抽屉，不跳页（S12）

| 项 | 规定 |
|---|---|
| 容器 | `Drawer` + `showDrawer` / `hideDrawer`；**禁止** `navigate` 到详情页 |
| 宽度 | **560**（`.ant-drawer.w-lg` 变体；容器原为 420） |
| 触发 | 整行 `rowClick: true`；操作列按钮 `stopPropagation` |

**声明 ≠ 渲染（和列宽缺 `px` 是同一类坑）**：只在 JSON 里写 `props.width: 560` **不够** —— 渲染器必须据此加上 `.ant-drawer.w-lg` 类，否则它仍然是 420px，而只读 JSON 的判据会显示「560 已达标」。验收时必须**打开抽屉**量一次 `document.querySelector('.ant-drawer').offsetWidth`，看它是不是 560；只贴 JSON 里的 `width: 560` 不算证据。

**为什么不用跳页**：跳页会抹掉「我在看第几行」—— 用户看第 14 行，进去再回来，滚动位置、筛选条件、页码全丢，只能重新找到那一行。抽屉保留父页的筛选、页码与滚动位置。

**为什么是 560 而不是更宽**：866 档内容宽下，560 抽屉还剩 **306** —— 刚好能露出当前行的主键与状态，用户能确认「我看的还是那一条」。720 会把列表压到 146，只剩半列，等于跳页；420 装不下「字段 + 操作 + 子表」，用户要横向滚动。

**什么时候该跳页**：详情本身是工作台（时间线 + 多 tab + 审批流 + 独立 URL 要分享），见 §3.2「新页面」。

### 0.9 写完之后逐条过（形态 A 自检）

- [ ] §0.1 两条都成立（不是靠浏览发现的页面）
- [ ] 行 ≥20、列 ≥8（866 档 8 列 / 1026 档 9 列，生成时定死）
- [ ] 每列都写了 `width`，`Σ = 866`（±2，唯一一套列集；1026 / 1284 不按该档内容宽闭合），每列 ≥48，`table-layout:'fixed'`
- [ ] 主键三列不裁字；`ellipsis` 配置列数 ≤3，且与真溢出列集合相等（866 档实测恰 2 列：物资名称 / 质检标准）
- [ ] 筛选区是 `filterBar:'grid3'` 两行三列；label 76 右对齐；控件没写 `min-width`
- [ ] `Table.size` 写了 `'xs'`（不是空、不是 `'middle'`）
- [ ] `stickyHeader` + `maxHeight` + `stickyFooter` 三件齐全
- [ ] 标题带里 h1 存在、≥16px/600，**不是**拿面包屑末级当标题
- [ ] 提示条 / 主操作 / 工具条没有各自成行（三合一，§0.5）
- [ ] 列表页 `Statistic` = 0；要数量用标题带 `Segmented`
- [ ] 行内彩色 Tag ≤1（状态色块算 1 类）；「加急=否」这类默认值渲染 `—` 灰字，不上色
- [ ] 数值列 `align:'right'` + `num`，单位与数值分离
- [ ] `total ≥100` 时 `pageSize ≥20`
- [ ] 六态齐全，`s-empty` 与 `s-no-result` 的文案和动作不同
- [ ] 详情是 560 抽屉，不是跳页；点行开、点行内按钮不误触
- [ ] 页面级 `primary`：标题带内恰 1 个，与 h1 的 `top` 差 ≤8；全页 ≤2（第二个只能是「查询」）
- [ ] 页内字号 ≤3 档（18 / 14 / 12）

> **去掉 `table-layout:'fixed'` 会让 P7 与 P18 同时红** —— 前者判列宽声明率，后者在 auto 布局下前置不成立直接判 FAIL（不是 SKIP）。所以「不写 fixed 就少判一条」不成立。

## 1. 三种容器的本质定位

| 容器 | 模态级别 | 与父页面关系 | 典型宽度 | 核心心智 |
|------|----------|--------------|----------|----------|
| 对话框 Dialog | 强模态（遮罩、强制处理完） | 完全脱离上下文，处理完即回 | 400–560px | 打断式、聚焦、轻量 |
| 抽屉 Drawer | 半模态（父页面仍可见） | 保留上下文，侧边滑出 | 右滑 480–720px / 全屏 90vw（作业型列表页的详情固定 **560**，见 §0.8） | 上下文、对照、快速往返 |
| 新页面 Page | 无模态（整屏切换） | 完全独立，URL 独立 | 100vw | 深工作流、长时专注 |

**一句话记法**：对话框是「打断」，抽屉是「并排」，新页面是「进入」。

---

## 2. 决策树（按顺序判断，命中即停）

```
1. 内容是否轻量且需快速返回？
   ├─ 是 → 对话框（≤3 字段 / 纯确认 / 强耦合原流程）
   └─ 否 → 下一步
2. 是否需要对照父页面，且内容中等？
   ├─ 是 → 抽屉（多字段单屏 / 详情主从 / 边看边操作）
   └─ 否 → 新页面（复杂、多步、独立 URL、需长期停留）
```

判断时问自己三个问题：
- 用户**要不要回头看**原来的列表？（要 → 抽屉）
- 用户**会不会在这里待很久**？（会 → 新页面）
- 用户**是不是只想点个确认**？（是 → 对话框）

## 3. 按场景给准则

### 3.1 表单录入

| 容器 | 什么时候用 | 例子 |
|---|---|---|
| 对话框 | 单字段 / 少量字段的快速编辑、批量操作确认、筛选设置、简单创建 | 改状态、改价格、批量启用、设置筛选条件 |
| 抽屉 | 中等复杂度的新建 / 编辑，且需要边填边参照列表或其他数据 | 新建工单（需看客户历史）、编辑配置项、带参照的选择 |
| 新页面 | 复杂表单（多 section、分步向导、跨模块数据整合、需上传多文件、可保存草稿） | 新建复杂合同、完整报价单、多步 onboarding |

**硬阈值**：**表单字段 > 15 个，禁止用对话框**（校验器 ERROR）。滚动、校验、键盘体验都会崩。

### 3.2 详情页

| 容器 | 什么时候用 | 例子 |
|---|---|---|
| 对话框 | 只适合「少量只读字段的快速确认」，**不适合「详情 + 操作」** | 看一眼地址、确认一个编号 |
| 抽屉（最常用） | 主从列表结构，点列表行看详情，边看边回列表；详情含少量操作（审批、备注、驳回） | 订单快速预览、工单处理、客户速览 |
| 新页面 | 详情本身就是一个工作台 —— 含时间线、关联记录、多 tab、编辑入口、审批流 | 订单详情页、客户 360 视图、设备档案 |

**抽屉最大的价值是「保留父页筛选 / 滚动状态」** —— 用户看完详情回到列表，筛选条件、页码、滚动位置都还在。新页面做不到这一点。

> **作业型列表页的详情一律 560 抽屉**（不是 420、不是跳页）：866 档下 560 抽屉还剩 306 能看到当前行。完整规定见 §0.8。

## 4. 五维决策矩阵

| 判断维度 | 对话框 | 抽屉 | 新页面 |
|----------|--------|------|--------|
| 内容量 | 1–3 字段 | 多字段单屏 | 多 section / 多步 |
| 上下文依赖 | 无需参照 | 需参照父页 | 自成体系 |
| 任务时长 | 秒级 | 分钟级 | 长时 |
| 需独立 URL / 可分享 / 刷新保留 | 否 | 通常否 | 是 |
| 与列表耦合 | 强（看完即回） | 中 | 弱 |

## 5. B2B 复杂系统的特有准则（重点）

1. **详情主从首选抽屉**，别用对话框 —— 对话框展不开关联信息和操作区。
2. **禁止对话框套对话框（dialogception）**：第二层一律改用抽屉或新页面。*（校验器 ERROR）*
3. **长表单（> 15 字段）禁用对话框**。*（校验器 ERROR）*
4. **需要全屏专注的复杂编辑用新页面**，抽屉的半屏会限制信息密度。
5. **危险操作 / 批量确认用对话框**：利用强模态强制用户确认。
6. **状态保持规则**：
   - 抽屉关闭**保留**父页状态（筛选 / 页码 / 滚动）；
   - 新页面切换要支持草稿保存 + 未提交离开提示；
   - 对话框 / 抽屉关闭**默认丢弃**未保存（除非显式自动存草稿）。
7. **抽屉方向约定**：右滑用于详情 / 编辑，左滑常用于筛选面板或导航。
8. **抽屉里塞多 tab（≥3）的工作台要升级为新页面**。*（校验器 WARN）*

## 6. 反模式速查

| 反模式 | 后果 | 应改为 | 校验器 |
|---|---|---|---|
| 用对话框承载 20 个字段的长表单 | 滚动 / 校验 / 键盘体验灾难 | 抽屉或新页面 | **ERROR** |
| 对话框里再弹对话框处理二级流程 | 遮罩叠遮罩，用户迷路 | 抽屉或新页面 | **ERROR** |
| 详情用对话框 | 展不开关联信息、时间线、操作区 | 抽屉（主从）或新页面（工作台） | WARN |
| 抽屉里塞需要切多 tab 的复杂工作台 | 半屏装不下，横向挤压 | 新页面 | WARN |
| 频繁切换新页面打断列表里的连续操作流 | 每次都丢失筛选与滚动位置 | 抽屉 | 人工判断 |
| 主子表把两张表平铺、点上行下行不动 | 用户以为页面卡了 | 用 `MasterDetail` 做联动 | 人工判断（见 §7.3） |

## 7. 映射到容器（怎么写）

### 7.1 对话框 → `Modal`

```jsonc
{ "id": "n-modal-del", "type": "Modal",
  "props": { "modalId": "m-del", "title": "删除巡检任务", "open": false,
             "content": "删除后不可恢复，确认删除？", "okText": "删除", "cancelText": "取消" } }
```
- 打开 / 关闭：`{"type":"showModal","modalId":"m-del"}` / `{"type":"hideModal","modalId":"m-del"}`。
- 底部按钮的合成 id 是 **`<Modal 节点 id>__ok` / `__cancel`**（注意：用的是 **Modal 节点 id**，不是 `props.modalId`）。
- `__cancel` 由容器内建关闭，作者不必写 interaction；`__ok` 需要自己写（通常 `hideModal` + `message`）。

### 7.2 抽屉 → `Drawer`

```jsonc
{ "id": "n-dr-edit", "type": "Drawer",
  "props": { "modalId": "dr-edit", "title": "修改巡检任务", "open": false,
             "placement": "right", "width": 520 },
  "children": [ /* 表单 */ ] }
```
- 打开 / 关闭：`showDrawer` / `hideDrawer`，键名是 `drawerId`。
- 抽屉里的按钮是**普通节点 id**（没有合成 id），要自己写 interaction。

### 7.3 新页面 → `pages[]` + `navigate`

```jsonc
{ "id": "page-inspect-task-detail", "name": "巡检任务详情", "route": "/inspect/task/:taskNo",
  "parentId": "page-inspect-task",              // 左侧导航树里挂在列表页下面
  "states": [ { "id": "s-default", "vars": { "taskNo": "ONSETE-20261016-0043" } } ] }
```
- 跳转：`{"type":"navigate","pageId":"page-inspect-task-detail","params":{"taskNo":"{{row.no}}"}}`。
- **目标页必须能用 `states[].vars` 的默认值独立渲染** —— 否则直接打开链接或刷新就会白屏。
- 页面自带返回：`Header` 加 `props.back: true`，或写 `{"type":"back"}`。

### 7.4 主子表 → `MasterDetail`（本页数据层级多时优先考虑）

**判断标准**：同一条主记录下挂着若干明细，用户需要**边扫主表、边看某一条的明细**。
典型：一条巡检任务 → 若干巡检项；一张订单 → 若干商品行；一台设备 → 若干保养记录。

```jsonc
{ "id": "n-md-task", "type": "MasterDetail",
  "props": { "bind": "no", "bindTo": "taskNo",   // 主表字段 → 子表字段
             "detailTitle": "巡检项", "collapsible": true, "autoSelectFirst": true },
  "children": [
    { "id": "n-task-table", "type": "Table", "props": { /* 主表，radio 单选行 */ } },
    { "id": "n-item-table",  "type": "Table", "props": { /* 子表，按 taskNo 过滤 */ } }
  ] }
```

- **不要**把两张表平铺成兄弟节点 —— 那样点上行下行不会动，看起来像页面卡了。
- 主表**不要**设 `props.rowClick`（点行 = 选中行，容器会强制关掉并报 ERROR）。
- 完整契约见 `04-container-schema.md` §6.7；可运行示例见 `assets/examples/example-04-master-detail.json`。

## 8. 一句话口诀

> 轻量确认用弹窗，对照上下文用抽屉，复杂长程用新页；
> 一批单据要扫要批处理 → 全宽列表 + 560 抽屉（形态 A）；
> 详情主从首选抽屉，禁套弹窗；
> 一条主记录挂多条明细，用主子表。

## 9. 自检清单（写 PRD 时逐条过）

> 如果这一页是**作业型列表页**（§0），先过 §0.9 的 12 条，再过下面这些 —— 两张清单不重复：§0.9 管形态与密度，本节管容器合规。

- [ ] 每个 `Modal` 的字段数 ≤ 15（含 `FormItem` 里的控件）
- [ ] 没有任何 `Modal` 嵌套 `Modal`
- [ ] 承载「详情」的容器不是 `Modal`（详情用 `Drawer` 或新页面）
- [ ] 抽屉里没有 ≥3 个 tab 的工作台
- [ ] 详情页（新页面）在 `states[].vars` 里留了默认值，可独立渲染
- [ ] 主从结构（一条主记录挂多条明细）用了 `MasterDetail`
- [ ] 危险操作（删除 / 作废 / 批量）走了 `Modal` 强模态确认
- [ ] 在 PRD 的「交互说明」里写清楚**为什么选这个容器**（一句话即可）

## 10. 反模式：形态选错（比容器选错更常见）

| 反模式 | 后果 | 应改为 |
|---|---|---|
| 8 个字段的作业单做成卡片宫格 | 一天点 200 次找不到目标条；无法跨行比对 | 形态 A（§0.2） |
| 「浏览 / 逛」型内容做成 8 列密表 | 失去视觉扫描入口；用户不知道从哪看起 | 形态 B（卡片） |
| 作业型列表放进 ≤640 窄栏 | 每列 <80px，主键列全部裁字 | 折叠左栏 / 全宽预览，不是删列 |
| 用 `navigate` 跳详情页代替抽屉 | 回来丢掉页码、筛选、滚动位置 | 560 `Drawer`（§0.8） |
| 列表页顶部放 4 张统计卡 | 表格被推出首屏；数字与筛选不同步 | 标题带 `Segmented` 或独立统计页（§0.6） |
| 筛选区控件写 `min-width` | 三列栅格被撑成 6 行 1 列，筛选区 40 → 194 | 宽度由栅格算（§0.4） |
| 空态与零结果共用「暂无数据」 | 用户不知道该建还是该改条件 | `s-empty` / `s-no-result` 分开（§0.7） |
| 列宽只写在文档里没写进 `columns` | 布局退化成等宽，主键列裁字 | 每列 `width` + `table-layout:'fixed'`（§0.3） |
